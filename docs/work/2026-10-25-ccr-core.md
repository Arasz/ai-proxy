# CCR preview and retrieval core

PR [#66](https://github.com/Arasz/ai-proxy/pull/66) adds deterministic tool-result previews and `proxy_retrieve` answers. `CcrPreviewBuilder.Build` selects original lines within a budget and identifies hidden ranges. `CcrRetriever.Answer` uses the injected `CcrRetrievalParser` to validate tool arguments, then returns numbered lines, pattern windows, or the exact original after a header.

This is an inactive implementation slice. The host does not call these operations, inject the tool, retain originals, or intercept retrieval calls. There is no runtime release or version change here. Activation still requires the design gate in [#64](https://github.com/Arasz/ai-proxy/pull/64), host integration, readable originals before hints, streaming and thread handling, and the acceptance gates in the [activation record](2026-10-24-csharp-reducer-activation.md).

The builder owns the selection and assembly state and composes smaller methods for each stage. Its injected `CcrPreviewOverlay` owns the identifier overlay state. `CcrRetriever` and `CcrRetrievalParser` are the retrieval components, and results are named records rather than tuples. The host registers all four as transient services when compression is enabled. Each instance handles one operation at a time and clears its state between operations. Shared text hashing and line splitting are stateless helpers in Core. Registration provides composition without activating CCR in the pipeline.

`CcrOptions.Default` carries the owner's ADR 0005 rulings of 2026-10-25: a 3,000-token minimum, a 1,500-token preview (O2) and a 3,000-token `lines`/`pattern` cap (O12). All three are configurable, and `CcrOptionsTests` pins them as literals. The byte baseline in `CcrPreviewTests` runs at the 1,000/4,000 sizes it was captured at, so it keeps proving the component refactor changed no output.

## Progress and validation

The parent task graph is `aip-whole-request-compression-and-retrieval`, step `ccr-implement`. This slice supplies evidence for its `deterministic` criterion. Its `roundtrip` criterion stays outstanding until an integration test proves the host answers retrieval inside one client response. The linked finish graph is `aip-finish-ccr-core-review`.

The unit suite covers repeatable and culture-independent previews, content hashes, line coverage, budgets, retrieval caps, malformed arguments and exact whole-text recovery. Independent review found malformed Unicode arguments escaping the error contract and pattern windows splitting surrogate pairs. Regression tests exercise those cases and the existing preview cut boundary. Mutation QA verifies that changing whole retrieval to trim the original makes the exact-text test fail.
