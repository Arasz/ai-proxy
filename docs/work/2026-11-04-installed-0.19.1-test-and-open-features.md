# Installed 0.19.1 smoke test and the open feature list

**Date:** 2026-11-04
**Question:** Does the published 0.19.1 tool work end to end on this machine, and which planned features are still missing at `origin/main` `d22e455` (VERSION 0.21.0)?

0.19.1 is the newest version on NuGet. Main already carries 0.19.2, 0.20.0 and 0.21.0, none of them published yet.

This record replaces the open list in [2026-10-31-planned-features-and-gain-table-width.md](2026-10-31-planned-features-and-gain-table-width.md). Since that record was written, F1 and F2 (compact gain numbers) shipped in 0.19.2, D6 (the per-region size minimum) in 0.20.0, and D5 (the build-output kind) in 0.21.0.

## Smoke test of the installed tool

The test used the global tool `ai-proxy` 0.19.1, with a live instance started by `ai-proxy --restart` and listening on 8080, API on 17432.

| Check | Result | How |
|---|---|---|
| `--version` | `0.19.1` | CLI |
| Pass-through of a non-provider host | 200, TLS tunnelled | `curl -x 127.0.0.1:8080 https://example.com` |
| Provider inspection | Leaf `CN=api.anthropic.com` issued by `CN=ai-proxy local inspection CA`; upstream 401 relayed unchanged | `curl -v -x ... https://api.anthropic.com/v1/messages` without a key |
| Name-constrained root (ADR 0009) | `X509v3 Name Constraints: critical`, permitted `openai.com`, `anthropic.com`, ...; valid to 2036 | `security find-certificate` piped to `openssl x509 -text` |
| `gain` text and `--format json` | Both render live store totals (4,8xx requests) | CLI |
| `mcp` `initialize` and `tools/list` | `retrieve_original` advertised, logs on stderr only | JSON-RPC over stdio |
| `mcp` `tools/call retrieve_original` | Returned lines 1 to 3 of a preview this session had just received | JSON-RPC over stdio |

Two defects showed up:

1. **The gain table splits numbers mid-digit at 80 columns** (`271,78` over `0,847`). This is F1 of the 2026-10-31 record. It is fixed on main in 0.19.2 but isn't published, so installed users still see it.
2. **`ai-proxy mcp` drops replies still in flight when stdin closes.** If you pipe three requests and close stdin, the handlers run (the log says they completed) but nothing reaches stdout. If you keep stdin open for three seconds, every reply arrives. Real MCP clients keep stdin open, so this is low impact. A script, or a CI smoke test, will see empty output, though. Not yet filed.
