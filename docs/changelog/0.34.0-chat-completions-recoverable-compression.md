# 0.34.0: recoverable compression for Chat Completions on OpenRouter

Streamed Chat Completions requests to `openrouter.ai` now get previews of large tool results that
the model can read back with `proxy_retrieve`, as Anthropic Messages requests already did. The
decision is
[ADR 0016](../adr/0016-recoverable-compression-for-chat-completions-on-openrouter.md).

- It applies when the host is `openrouter.ai`, the request is a POST to a path ending in
  `/chat/completions` with `stream: true` and tools, and the model id starts with `anthropic/`,
  `openai/`, `google/` or `deepseek/`. A router model (`openrouter/auto`), an unknown prefix,
  `n` above 1, and a `tool_choice` of `none` or another function keep forwarding without previews.
  `api.openai.com`, `eu.openrouter.ai` and `chatgpt.com` are unchanged.
- The mode is stateless. `proxy_retrieve` is appended last in `tools` as a function tool, and
  `stream_options.include_usage` is turned on upstream; every other byte of the request is kept.
- The proxy holds `tool_calls` deltas until `finish_reason`, joins them by `index` (a reused
  index with a new id starts a new call), and answers `proxy_retrieve` calls itself when the
  turn ends with `tool_calls` or `stop`. On `length` or `content_filter` the client's calls go
  through and `proxy_retrieve` calls are dropped and logged. The client never sees them, sees its own calls numbered from 0,
  and gets one stream with one `data: [DONE]`.
- A `proxy_retrieve` call made next to a client call is answered, and the client call gets the
  "not run, issue it again" result. Every `tool_call_id` gets a `role: "tool"` reply, and reasoning
  the model returned is sent back in the follow-up (a later `"reasoning": null` keeps the text,
  and `reasoning_details` pieces are joined by `index`).
- Usage from every round is summed field by field (prompt, completion and total tokens, cost and
  the details) into the last chunk. The chunk is dropped when the client did
  not ask for usage.
- Upstream `: OPENROUTER PROCESSING` comments reach the client, and while a follow-up runs the
  client gets `: keep-alive` comment lines every `Proxy:Ccr:KeepAliveInterval` (default 5 s). A refused follow-up or an upstream
  error becomes an error chunk, then `[DONE]`.
- Follow-up and recall rows carry the request host, so they show under `openrouter` in
  `ai-proxy gain`.
- The Anthropic path behaves as before. `Proxy:Ccr:Enabled` switches both paths;
  `Proxy:Ccr:UnknownProviders` still has no effect.
