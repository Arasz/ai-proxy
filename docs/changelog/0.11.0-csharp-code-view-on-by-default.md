# 0.11.0 - C# code view, on by default

A whole C# file that a tool call read now goes upstream as its code view, and the model can read
the exact file back with `proxy_retrieve` (CCR, [ADR 0005](../adr/0005-tool-result-previews-with-in-request-retrieval.md)).

- **Code view.** When the tool call that produced a result names a `.cs` file and the result is the
  whole file, the result goes out with comments and `using` lines removed. Line numbers of a
  numbered read stay as they were. The view ends with one line:
  `[proxy view <id>: comments and imports removed. Call proxy_retrieve with this id for the exact file.]`
  A file the view does not make smaller, including that line, keeps the blank-line reduction.
- **Original first.** The view leaves the proxy only when its original can be retrieved: carried with
  a stateless request, or written to the content database first in a thread. If that write fails,
  the result goes out unchanged and the failure is logged. Requests without CCR (no tools, other
  providers, `PROXY__CCR__ENABLED=false`) never get a view.
- **Ids.** The id is the same content hash a preview uses, so a file large enough for a preview is
  sent as the preview of the original, under the same id.
- **Switch.** `Proxy:Compression:CodeViews` defaults to `true`; set `PROXY__COMPRESSION__CODEVIEWS=false`
  to keep source files on the blank-line path.
- **Prompt cache.** The same file gives the same view bytes on every send. The first request after the
  upgrade differs from what 0.10.0 sent for the same conversation, once.

Not covered: Python, JavaScript and TypeScript views (the lexers exist; they are not registered yet).
