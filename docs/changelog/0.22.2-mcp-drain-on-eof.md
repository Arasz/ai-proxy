# 0.22.2: `ai-proxy mcp` answers requests that are still running when stdin closes

When a client sent its requests and closed stdin right away, `ai-proxy mcp` printed nothing. For example, piping `initialize`, `notifications/initialized` and `tools/list` into it gave an empty stdout, because the MCP library stops sending replies as soon as it reads the end of input.

The server now waits at end of input until every request it has read has been answered, then exits with code 0. A request that the client cancels with `notifications/cancelled` stops counting, and lines that are not valid JSON-RPC are ignored. If a request never gets an answer, the server gives up after 30 seconds and exits anyway. A stream with only notifications still exits at once.

Logging stays on stderr, and stdout is written and flushed the same way as before.
