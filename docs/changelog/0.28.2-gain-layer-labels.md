# 0.28.2: every gain layer is named

`ai-proxy gain --by-layer` listed most requests under `unknown`, although the proxy knew what it did to them. Each request now records one of these layers:

- `tool_result`: the proxy reduced tool output.
- `ccr_tool`: the only change is the injected `proxy_retrieve` definition, so the row shows that cost on its own.
- `none`: the request went upstream unchanged, or was refused because the retrieval ledger was unavailable. Non-model traffic such as telemetry is `none` too.
- `retrieval`: recalls and the follow-up requests that answer them, whether they come from `proxy_retrieve` or the `retrieve_original` MCP tool.

Recalls and follow-ups made inside a request now also take the pipeline `ccr`, as `retrieve_original` recalls already did.

Before, a recall counted under the layer and pipeline of the request that made it. So `--layer tool_result` subtracted what reading the originals back cost. That cost now sits under `retrieval` and `ccr`, so use the summary or `--by-rule` for the net of a reduction.

The first start on 0.28.2 rewrites the existing ledger once, so old and new rows agree. It names each `unknown` layer from the stored rule, and moves recalls and follow-ups to `retrieval` and `ccr`. `unknown` is now left for values the proxy really does not know.
