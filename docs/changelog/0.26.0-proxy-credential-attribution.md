# 0.26.0: project attribution through the proxy credential

Codex's built-in provider cannot add headers, so its traffic used to show as unattributed in `gain`. It now carries its project in the proxy URL.

- `ai-proxy harness` sets `HTTP_PROXY`, `HTTPS_PROXY`, `http_proxy` and `https_proxy` to `http://ai-proxy:<percent-encoded project path>@host:port` for every harness, not only Codex. Clients that honour proxy userinfo (Codex 0.166.0 and Claude Code 2.1.318 were measured) send it as `Proxy-Authorization: Basic` and the proxy reads the project from it.
- The proxy takes the project from the `X-Ai-Proxy-Project` header first, then a `Proxy-Authorization` on the request, then one on the CONNECT that opened the tunnel. Only a Basic credential with user `ai-proxy`, valid UTF-8 and a non-empty password without a newline counts; anything else is ignored.
- The proxy never requires proxy authentication. A client without a credential is served as before.
- The proxy removes `Proxy-Authorization` from every request it forwards, including plain HTTP to hosts it does not inspect.
- `--proxy` still rejects a URL with credentials.

WebSocket turns and `chatgpt.com` (ChatGPT sign-in) are still not recorded. See [reading gain](../how-to/reading-gain-and-retrieving-originals.md#split-the-numbers-by-project) and [ADR 0011](../adr/0011-project-attribution-through-proxy-credentials.md), which is still a Draft pending owner acceptance.
