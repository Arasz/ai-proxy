# 0.25.1: a stored original is no longer reported missing while the writer moves it

Reading a kept original (`GET /content/{id}`, `proxy_retrieve`, the MCP `retrieve_original` tool) could answer 404 for a record that existed. The read looked in the content tables first and in the queue second, so a record the writer moved between the two lookups, inserted into the tables and then deleted from the queue, was found in neither.

The read now looks in the queue first and in the tables second. The writer commits the table row before it deletes the queue job, so a record is always in at least one of them at the moment each is read.
