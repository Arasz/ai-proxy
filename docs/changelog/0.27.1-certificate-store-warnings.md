# 0.27.1: certificate store failures are warnings

A start that replaced the root certificate on macOS printed `[ERROR] Titanium.Web.Proxy: Certificate operation failed` with a stack trace, once for adding the new root and once for removing the old one. Nothing was wrong: .NET cannot write to the macOS root store, so that step always fails and the system `security` tool does the work.

These failures now appear as a one-line warning (event 1310) in the normal ai-proxy log. Titanium's trust step also uses the ai-proxy logger now, instead of Titanium's own console logger.

A failure to remove a replaced root no longer stops the start. It logs a warning (event 1311) that names the thumbprint, so the old root can be removed by hand. A new root that stays untrusted still stops the start.
