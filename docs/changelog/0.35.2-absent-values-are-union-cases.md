# 0.35.2: absent values are union cases, not null

Internal refactor under [ADR 0022](../adr/0022-absent-values-are-union-cases-not-null.md),
waves 1 and 2. No behaviour changes: log text, JSON output, HTTP problem details and gain
database values are the same. Shipped in [#170](https://github.com/Arasz/ai-proxy/pull/170) and
#172.

## Changes

- **A parsed `proxy_retrieve` call is a union.** `CcrParseResult` is the request or a refusal
  with its reason. Callers parse once and switch on the case.
- **A retrieval answer is a union.** `CcrAnswer` is `CcrFound` or `CcrFailed` with its error
  code. `CcrRetrieval` keeps the tool name, definitions, error codes and factories.
- **One shared `Validation` union.** The tool argument schema and the gain API return `Valid` or
  `Invalid` with a reason, not a nullable message.
- **CLI settings checks throw.** `DoctorSettings`, `GainSettings`, `ReplaySettings` and
  `StatusSettings` have `Check`, which throws the same `ArgumentException` as before.
- **Optional record fields are `init` properties.** `CheckResult.Fix`,
  `HandledContent.RetrievalId`, `ContentRegion.FilePath`, `ReplayBlock.PreviewId`,
  `ReplayRow.Host`, and `CompressionResult.StoreFailure` (was `Failure`) and `Summary`.
- **A nullable inventory.** `scripts/nullable-inventory.py` lists nullable declarations by
  category; [the inventory](../work/2026-11-22-nullable-inventory.md) holds the wave plan.
