# 0.15.0 - Gain and retrieval clients in the ai-proxy tool

The proxy now records what it saved and serves it, with kept originals, to two new commands of the
same `ai-proxy` tool ([ADR 0006](../adr/0006-one-tool-with-local-gain-and-retrieval-clients.md);
[how-to](../how-to/reading-gain-and-retrieving-originals.md)).

- **Local API.** `GET /gain`, `POST /gain/reset` and `POST /retrieval` on `http://127.0.0.1:17432`.
  **Default port change:** the health and content endpoints move there too, from `http://localhost:5000`.
  `ASPNETCORE_URLS` or `--urls` still wins.
- **Gain ledger.** Every inspected provider request is recorded, unchanged and failed ones included,
  with measured characters and bytes of the body actually forwarded (the `proxy_retrieve` definition
  counted) and estimated tokens at 2.89 characters per token. Each `proxy_retrieve` answer is
  recorded as a recall. Reports filter by date, project, provider, method, rule, layer and pipeline,
  bucket by UTC day, Monday week and month, and reset by filter without touching kept originals.
- **`ai-proxy gain`.** Text, JSON or CSV views of the summary, history, buckets, attributions,
  failures and recalls; `--watch` for a live view; `--reset` with a confirmation.
- **`ai-proxy mcp`.** A stdio MCP server with one read-only tool, `retrieve_original`, over the same
  retrieval as `proxy_retrieve`. Only thread-mode originals outlive their request.
- **Project attribution.** Send `X-Ai-Proxy-Project`; the proxy strips it before forwarding.

Statistics start with this release. Savings are estimates of the first request only; retrieval cost
is shown separately.

Shipped in #73.
