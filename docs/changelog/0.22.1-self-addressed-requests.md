# 0.22.1: a request sent to the proxy port itself gets a clear answer

When a client called the proxy port as if it were a web server, for example with a base URL of `http://127.0.0.1:8080`, Titanium refused to connect to itself. The proxy logged an unhandled exception with a full stack trace, and the client got an empty reply.

Now the proxy answers `400` with one line of text: the port is a forward proxy, so set it as `HTTP_PROXY` or `HTTPS_PROXY`, not as a base URL. It logs a single warning (event 1309) with the method, the path and the User-Agent, so you can tell which client is misconfigured.

When the proxy sets the system proxy, it now also adds `localhost`, `127.0.0.1` and `::1` to the bypass list, next to the entries already there. Local calls go straight to their target instead of looping back into the proxy.

`ai-proxy doctor` takes `--timeout <SECONDS>` (default 5). On a busy machine the first inspected handshake, where the proxy creates a certificate, could take longer than five seconds and show as unknown.
