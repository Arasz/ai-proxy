# 0.29.0: .NET 11 and Runtime Async

ai-proxy now targets .NET 11 (SDK 11.0.100, pinned in `global.json`). Installing or updating the tool needs the .NET 11 runtime; .NET 10 alone will no longer run it.

Every .NET 11 project compiles with Runtime Async turned on (`<Features>runtime-async=on</Features>`, set in `Directory.Build.targets`). The runtime now suspends and resumes async methods itself, so the compiler no longer generates a state machine class for each one. Live call stacks in a debugger or profiler show the async methods instead of that machinery. Runtime Async is a preview feature in .NET 11. The source generator stays on `netstandard2.0` and is left out. `RuntimeAsyncTests` fails if any async method in `AiProxy`, `AiProxy.Core` or `AiProxy.Storage` compiles back to a state machine.

Package updates: `Microsoft.Data.Sqlite` 11.0.0, `Microsoft.Extensions.TimeProvider.Testing` 11.0.0, `Titanium.Web.Proxy` 8.0.2 (from 7.0.26), `ModelContextProtocol` 2.4.0, `JsonSchema.Net` 9.6.0, `Microsoft.NET.Test.Sdk` 18.12.0 and `xunit.v3` 4.0.3. .NET 11 ships `Microsoft.Extensions.Logging.Abstractions` with the framework, so `AiProxy.Code` and `AiProxy.Storage` no longer reference the package. The unused `Microsoft.Extensions.Hosting` version entry is gone.
