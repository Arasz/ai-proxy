# 0.7.1: a dropped upstream stream fails at the client

**Released:** 2026-10-24
**PRs:** #40

When an upstream closed or reset its connection between two chunks of a chunked response, such
as a provider event stream cut between events, the client waited until its own timeout. Titanium
reads a chunked body that ends at a chunk boundary as complete, so it never closed the client
connection, and the client kept waiting for the next chunk. This happened with capture and
compression off, and for pass-through traffic as well.

ai-proxy now closes the client connection after any exchange whose upstream connection has
closed, so the client sees the failure at once. A cut chunked response is logged as a warning
(event id 1306). A response that ends cleanly keeps the client connection for its next request.

Titanium does not expose the upstream connection state, so ai-proxy reads it from Titanium's
internal members. If a Titanium release renames them, ai-proxy logs an error once (event id
1307) and clients go back to waiting for their timeout; the integration tests fail in that case.
