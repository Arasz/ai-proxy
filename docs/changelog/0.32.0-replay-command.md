# 0.32.0: ai-proxy replay

`ai-proxy replay` is a new command that runs stored request bodies through the compression
pipeline as it is today and prints the saving. The decision is
[ADR 0015](../adr/0015-size-scaled-previews-read-and-diff-skip-and-a-replay-tool.md). This version
ships the tool only; the preview behaviour does not change.

- It builds the pipeline from the proxy's own service registrations and runs every request in
  stateless mode, with stores that keep nothing.
- It reads `content_request.original` from `content.db` and `capture_request.body` from
  `capture.db`, both opened read-only. Zstd capture bodies are decoded; a body that does not
  decode is counted as undecodable and not as a row with no saving.
- Options: `--minimum <tokens>`, `--since <date>`, `--source content|capture|both`, `--home <dir>`
  and `--json`.
- The output starts with the row counts: read, undecodable, not JSON, no tool region, misaligned,
  duplicate, replayed and with a preview, beside the capture rows and the gain requests of the same
  window. Then it shows one row per content kind and the saving summed per preview id.
- A body found in both databases is counted once.
- `ai-proxy gain` is unchanged. The how-to is
  [Replaying stored requests](../how-to/replaying-stored-requests.md).
