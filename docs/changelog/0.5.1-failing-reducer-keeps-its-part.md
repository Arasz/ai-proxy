# 0.5.1: a failing reducer keeps its part, not the whole request

**Released:** 2026-10-23
**PRs:** #31

A reducer that threw used to fail the whole compression stage, so the request went out with its
original body and every other part lost its reduction. Now only the part whose reducer threw
keeps its original text; the other parts in the same body are still reduced. The stored record
marks that part with the path `compression.handler-failed`, and the proxy logs a warning
(event 1402) naming the part, its content type, the provider host and the exception. A cancelled
request still stops the stage.

Stored records are now stamped through the host's `TimeProvider`.
