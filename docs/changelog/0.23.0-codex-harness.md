# 0.23.0: `ai-proxy harness codex` launches Codex through the proxy

`ai-proxy harness codex -- ...` now sets up what Codex needs, not only the proxy variables.

- Codex trusts the proxy's inspection certificate through `CODEX_CA_CERTIFICATE`, set to the root CA file. It replaces a value you set yourself, the same way `NODE_EXTRA_CA_CERTS` does for Claude Code. `SSL_CERT_FILE` is never touched.
- The launcher adds `--no-daemon` before your arguments, so an already running Codex daemon cannot carry the session around the proxy. It adds nothing when the first argument is `remote-control` or `app-server`, or when you pass `--no-daemon` or `--remote` yourself.
- `AI_PROXY_CODEX_PROJECT` is exported with the current directory, so the documented `env_http_headers` setting for a custom provider attributes gain to the project without a manual export.

Other agents get none of this. Codex cannot add headers to its built-in `openai` provider, so that traffic shows as unattributed in `gain`. `ai-proxy doctor` now names `CODEX_CA_CERTIFICATE` next to `NODE_EXTRA_CA_CERTS` when the system does not trust the root.
