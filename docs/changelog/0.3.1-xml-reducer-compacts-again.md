# 0.3.1 — the XML reducer compacts again

**Released:** 2026-10-22
**PRs:** #14

The XML reducer was not running. Reading an attribute with a prefix threw on a document
that did not declare the prefix, and the reducer caught the throw and fell back to the line
rule, so every ordinary XML document was deduplicated instead of compacted. The path the
store keeps said `xml.dedupe` rather than `xml.compact`, and nothing looked.

The attribute is now read through its namespace, so nothing throws. The reducer also
learned the difference between the whitespace that formats a document and the whitespace
that is its content: the indentation between elements goes, and the space in
`Hello <b>world</b>` stays, as does anything under `xml:space="preserve"`.

## What a user gets

Nothing changes for a request that carries no XML. A request that carries XML now gets it
compacted, which is what the stage promised from the start, and the mixed content in a
document survives the reduction.

The corrections the owner asked for are in the two research records that pull request #3
brought in: the measured deduplication was a no-op, so the measured log reducer was the
signal filter and the two anchors at each end, and the rule-based prose path has no
measured benefit of its own because the deduplication it uses never fired in the
measurement. The records say so now.
