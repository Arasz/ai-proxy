# 0.25.0: `ai-proxy status` and `ai-proxy stop`

You can now ask the proxy whether it is running and shut it down without hunting for its process.

- `ai-proxy status` prints the pid, start time and uptime, the proxy and API URLs and the data directory. `-f json` gives the same for scripts. It exits 0 when an instance answers, 3 when none does, and 1 when something answers wrongly or not at all. The shutdown nonce never appears in its output.
- `ai-proxy stop` asks the running instance to shut down and waits for that exact process to exit, so the system proxy is restored the usual way. It exits 0 when it stopped the instance or none was running, and 1 when it could not (another start, restart or stop is in progress, the owner refused, or it did not answer in time).
- `stop` never kills a process and never judges by what is listening on the port.
- Both take `--data-directory`, falling back to `Proxy__DataDirectory` and then `~/.ai-proxy`.
- The "already in progress" message for a competing start now mentions stop as well.

Instances from before the control pipe existed cannot be seen by either command; stop those by hand. Details are in [lifecycle](../reference/lifecycle.md).
