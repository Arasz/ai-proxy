# 0.19.1: the root rotates when provider domains change

The `ai-proxy` root CA is limited to the provider domains the proxy inspects. When a release adds
a provider domain, the root on disk no longer covers it, and TLS to that host used to fail until
you deleted `root-ca.pfx` by hand.

Now the proxy compares the root's name constraint with the one the current hosts need. If they
differ, it makes a new root, trusts it and untrusts only the old one by thumbprint. The stored
password stays the same. The same hosts in any order keep the existing root.

After such an upgrade, expect one trust prompt, then restart every harness session. They read
`root-ca.pem` once, at start, so they keep the old root until restarted. The proxy logs this as
event 1308.

Upgrading from 0.19.0 does not rotate: the provider domains are unchanged.
