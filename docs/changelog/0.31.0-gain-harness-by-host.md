# 0.31.0: gain names the harness from provider and host

`ai-proxy gain` labelled every OpenAI-dialect request `codex`, so the pi agent's OpenRouter traffic
was counted as Codex. The decision is the 2026-11-20 amendment to
[ADR 0014](../adr/0014-gain-tables-fit-the-screen-and-count-each-rule.md).

- Each request row in the ledger now keeps the request host. The host is stored in the row's
  payload, so the database needs no migration.
- The harness comes from provider and host: `anthropic` is `claude`; `openai` on `chatgpt.com` is
  `codex`, on `openrouter.ai` is `openrouter`, on `api.openai.com` is `openai`. Regional hosts such
  as `eu.openrouter.ai` and `us.api.openai.com` map to the same harness. Anything else is `other`.
- Rows written before this version have no host. Their OpenAI traffic shows as `openai (host
  unknown)` and is not rewritten, because the ledger never kept the host.
- Follow-up and recall rows carry the host of their request, so they stay in the same harness row
  as that request instead of splitting into `openai (host unknown)`.
- Host matching ignores case and a trailing dot. `evilopenrouter.ai` and `notapi.openai.com` count
  as `other`, and any other `openai` host is `other`.
- The harness rows come from the same single query as the other summary rows, and they add up to the
  overall total.
- The summary table keeps `openai (host unknown)` on one line, with all six harness rows and
  `total` inside 80 columns.

The new rows appear once the running proxy is 0.31.0.
