# 0.4.1: clear the system proxy after a crash

**Released:** 2026-10-23
**PRs:** #23

A forced kill (SIGKILL, task manager, crash) used to leave the system HTTP and HTTPS proxy
pointing at a port nobody listened on. ai-proxy now starts a guard process, the same
executable run with `--guard-system-proxy`, right after it sets the system proxy. When the main
process dies without a clean shutdown, the guard clears the system proxy. After a clean
shutdown the guard exits without touching anything.

ai-proxy also keeps `~/.ai-proxy/system-proxy.lock` while the system proxy is set. If the
guard could not run (reboot, power loss), the next start finds the marker and clears the stale
proxy before setting it. A second ai-proxy instance now fails to start while the first holds
the marker.

A cleared proxy is not a restored one: after a forced kill, a proxy you had configured before
the run is not brought back. Normal shutdown still restores it.

The clear is unconditional. A proxy you set again after the crash and before the next start is
cleared too. If the restore on shutdown fails, ai-proxy logs an error and keeps the marker, so
the guard or the next start clears the proxy. The macOS backend swallows some of its own
errors, so a few failed restores stay invisible. The guard also ignores SIGTERM, and a guard
that ends early is logged without blocking a clean stop.
