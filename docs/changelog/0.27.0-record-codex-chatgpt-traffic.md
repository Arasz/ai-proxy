# 0.27.0: record Codex ChatGPT-sign-in traffic

Codex signed in with a ChatGPT account talks to `chatgpt.com`, which the proxy did not decrypt, so those turns were missing from `gain`. They are now recorded for harness sessions ([ADR 0012](../adr/0012-record-codex-chatgpt-subscription-traffic.md)).

- `chatgpt.com` is a harness-only provider host (OpenAI dialect). The proxy decrypts it only when the CONNECT carries the `ai-proxy harness` credential; browser and other system-proxy traffic stays an opaque tunnel.
- The root certificate now permits `chatgpt.com`, so it is replaced once at the next start. Accept the trust prompt and restart every `ai-proxy harness` session.
- A WebSocket upgrade to `/backend-api/codex/responses` on a harness tunnel gets HTTP 426 from the proxy; Codex then uses HTTPS for the session.
- Request bodies sent with `Content-Encoding: zstd` are decoded (up to 16 MiB) for capture and `gain`; the original bytes are forwarded. A body that does not decode is forwarded as sent and logged (event 1408). zstd bodies are never compressed.
- Harness-only hosts are record-only: their requests are never compressed or rewritten.
- Usage is read from the OpenAI Responses `response.completed` event and from Responses JSON bodies, so streamed `api.openai.com` Responses usage is recorded too. Cached input tokens count as cache reads.
- `ai-proxy doctor --host` refuses `chatgpt.com`: its check sends no harness credential.

Not yet proven live: whether `chatgpt.com` accepts the proxy's own upstream TLS connection. If Codex under the harness fails against `chatgpt.com`, run Codex without the harness.
