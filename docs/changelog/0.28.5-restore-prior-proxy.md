# 0.28.5: restore the exact prior proxy after a crash

ai-proxy now saves the system proxy settings it replaces in its marker file. If it crashes, the next start, or the guard, puts those exact settings back instead of just clearing the proxy. It restores them only while the settings still point at ai-proxy, so a proxy you set yourself in the meantime is left alone.

The proxy checks that it still owns the settings before every restore or clear, at startup, in the guard and at shutdown. A shutdown that finds newer settings leaves them and stops Titanium from restoring over them on exit. Startup logs whether it restored, skipped, or cleared an older marker (events 1312-1314; 1315 for a skipped shutdown restore).

The marker is written in one flushed write before the proxy is set. A record cut short by a crash is discarded with warning 1316 instead of blocking the next start. On Windows the marker is readable only by your user.

On macOS and Linux, ai-proxy also records the settings it applied, read back right after setting the proxy. Ownership then compares every restored value, the bypass list included: each must be ai-proxy's or the saved one, and at least one must still be ai-proxy's. A restore that stopped between HTTP and HTTPS is retried, and an outside change to any value (the bypass list too) is left alone. A marker without the applied settings, from an older version or a crash before they were written, keeps the older rule that HTTP and HTTPS must both still point at ai-proxy.
