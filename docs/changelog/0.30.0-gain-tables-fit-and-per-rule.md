# 0.30.0: gain tables fit the screen, use colour, and count each rule

`ai-proxy gain` was hard to read at 80 columns. Headers wrapped mid-word, `--history` printed full
GUIDs and paths over four lines, and `--by-rule` listed every rule *combination* the proxy recorded,
so it could not say what one rule saved. The decision is [ADR 0014](../adr/0014-gain-tables-fit-the-screen-and-count-each-rule.md).

- The summary is one table with a row per harness (`claude`, `codex`, `other`), and a `total` row
  when more than one harness has data. Short headers: Req, Orig, Fwd, Saved, Recall, Follow, Net, Saved%, Net%. The Tool column is
  gone; the injected tool definition's tokens are on the Method line.
- Saved and net figures are green when positive, red when negative and grey when zero. Colour is
  off when the output is not a terminal or `NO_COLOR` is set.
- `--by-rule` has one row per rule. A request that used several rules counts under each, so the
  rows overlap and do not add up to the total.
- `--rule X` matches requests whose rule path contains `X`, so it also matches combined paths.
  `--reset --rule X` deletes those whole requests, including the ones where `X` ran with other
  rules. A value with a comma, such as an old full path, still matches only that exact path.
- `--history`, `--recalls` and `--failures` show the last 8 characters of an id and the time
  without the year; `--history` and `--recalls` show the last folder of the project path. Very
  large percentages show as `>999%` or `<-999%`. `--format json` and `--format csv` keep the
  full values.
- Attribution tables sort by saved tokens, largest first.

The JSON `attributions` for `rule` now overlap in the same way. The per-rule rows appear once the
running proxy is 0.30.0, because the proxy computes them.
