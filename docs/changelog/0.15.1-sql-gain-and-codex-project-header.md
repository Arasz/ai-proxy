# 0.15.1 - SQL gain reports and Codex project attribution

`GET /gain` and `ai-proxy gain --watch` aggregate the gain ledger in SQLite. The report reads
only the requested number of history, failure and recall details into the application, while
the summary, calendar buckets and attribution still include every matching event. Existing
ledger files need no migration. Queries still scan matching ledger data; this change removes
the growing list of deserialized events from each report refresh.

The [gain guide](../how-to/reading-gain-and-retrieving-originals.md) now shows Codex's supported
`env_http_headers` configuration for `X-Ai-Proxy-Project`. An isolated Codex CLI probe verified
the outbound header with a fake API key and a local endpoint.

This release also includes #77: Tree-sitter grammar load failures log a warning, and the
blank-line fallback preserves blank lines inside Python triple-single-quoted strings.
