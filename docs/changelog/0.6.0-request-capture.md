# 0.6.0: request capture

**Released:** 2026-10-23
**PRs:** #TBD

`PROXY_CAPTURE=on` keeps a copy of every provider request the proxy reads, so you can measure
over a few days how real requests split into system prompt, tool definitions, turns, tool
results and thinking. Each request is one row in `~/.ai-proxy/capture.db` with a request id, the
time, the provider, the host, the path and the exact body bytes.

Capture never changes what is sent. The body goes upstream byte for byte, it works with
compression off, and with compression on it keeps the body from before compression. A capture
that fails to write is logged as a warning and the request goes out anyway. Startup logs the
file capture writes to.

No request headers are kept, and neither is the query string, so `Authorization`, `x-api-key`,
cookies and `?key=` values never reach the file. The body is kept in full, though, with whatever
the agent put in it. The file is user-only (`0600` in a `0700` directory on Linux and macOS) and
nothing prunes it, so delete it when the measurement is done. Capture is off by default.
